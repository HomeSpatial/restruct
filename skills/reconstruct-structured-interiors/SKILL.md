# 室内结构化重建

把扫描证据转为有语义对象、可编辑参数和明确不确定区域的室内模型。仅执行用户所需的重建、调查或编辑阶段；局部材质修正不启动整屋重建，只读诊断不改模型。

## 先建立当前任务的契约

- 确认输入扫描、照片及其相机内参与位姿属于同一次地图；记录路径、哈希、单位、轴向、原点和对齐变换。同名的 Unity 资产、显示网格、碰撞代理可能是不同版本。
- 从用户目标确定验收对象：视觉结构化、踏面与地板精度、门洞通行、水密建筑外壳或运行时碰撞。没有默认要求全部完成，也不能用其中一种通过代替另一种。
- 找到编辑真源：参数生成器还是 `.blend`。保留当前基线，在独立输出或副本上试验；先核实重建命令是否会重新提取并覆盖人工参数。
- 改动前明确哪些标高、边缘、对象或通道需要保持；“每级深度高度保持”通常指保留各级已有尺寸，若要统一踏步尺寸或改设计，先明确这一取舍。
- 任务目录的 `STATE.md`（init-task 生成；旧任务自行创建）是唯一的进度真源：开始建模前写定目标与各层验收依据，每轮原地改写当前接受版本、覆盖清单、问题表和下一步，只保留现状，不在末尾追加新段落；各轮经过写进另一个历史文件或报告。上下文压缩、换代理或续做时先读它，不依赖对话记忆。

## 按当前问题读取

- 使用通用 CLI、model v2 或执行独立场景任务：先读 [toolchain.md](references/toolchain.md)：新输入用通用 init-task 生成绑定，已有任务读取 startup.json，已有工程只执行需要的编辑阶段。
- 建模、照片核对、楼梯校准、家具和建筑闭合：读 [reconstruction.md](references/reconstruction.md)；整屋任务使用其中的“首版后的修正循环”，把检查发现转成下一轮局部修改。
- 精度失败、碰撞差异、拓扑验收或交付检查：读 [validation.md](references/validation.md)。
- 整屋重建进入外观阶段，以及颜色与材质标定、PBR、材质分界、Blender Agent 操作和 GLB 往返：读 [blender-materials.md](references/blender-materials.md)。整屋任务默认包含该阶段，不因用户未单独提到“贴图”而省略。

## 实施时的关键判断

先按文档 kind、模型版本和工程元数据识别接口：扫描 scene/frames 的 v1 契约不代表旧 ROS 模型；当前 model v2 与旧 Blender bundle 的轴向及导出规则见 [blender-materials.md](references/blender-materials.md)。

1. **先核实缺失的是几何还是显示。** 对照原扫描、RGB、完整高度、剖切、类别隐藏和背面剔除。桌面消失、墙总被截断、斜线分色可能来自不同环节。
2. **用结构表达结构。** 墙地顶采用共享边界的平面／体积，楼梯逐级表达，家具按可辨认部件组合。大片扫描残片换颜色或保留所有噪声边界，并不满足“真正结构化”。`category` 写物体本身是什么（wall、sofa、lamp、sink…），不写几何类型或角色；灯罩、扇叶、柜板等面板不能标为 wall。
3. **将证据与推断分开。** 保留对象来源、照片编号和局部不确定原因；遮挡背面、玻璃、缺失墙顶可按已知结构推断，但不冒充测量。诊断残网格单独显示。
4. **在同一查询域上比较修改前后。** 对已有问题先定位坏点、命中对象和引入它的改动，再选择修复；不要通过不断保留更多扫描碎片来掩盖边界拼接问题。
5. **交付可继续编辑的结果。** 稳定对象 ID、来源记录、编辑真源和可复现导出，比一次性截图更重要。若任务包括展示，实际检查常用视角和操作，再报告已实测结果。

场景任务可由单 Agent 完成；skill 不要求创建 subagent。需要委派时按用户授权和实际独立工作划分，同一参数工程保持一个写入者，其他工作返回证据或建议。

## 完成与维护

按任务目标判断完成：工具流程验证以接口与产物契约为准；重建任务还须处理范围内已确认的结构缺面、主体家具数量或形状错误；碰撞与行走按其独立验收执行。保存、重开或导出通过只证明对应流程。

整屋检查先用[来源到模型的覆盖清单](references/reconstruction.md#来源到模型的覆盖清单)发现未建和未查项，再进入局部修正；已有模型从当前问题进入。首版及交付前各运行一次[模型级诊断](references/validation.md#模型级诊断)（`restruct residuals` 找扫描有而模型无的区域，以及相机看穿的模型面，即模型多出或外凸的部分；`restruct check-geometry` 找穿插、共面重叠、外壳漏缝和类别误用），把结果逐项转成清单行或问题；它们给出位置和照片，不替代判断。日常重建把审查发现用于后续修复，只有用户明确要求盲测或冻结对比时才隔离评估反馈。按[修正循环](references/reconstruction.md#首版后的修正循环)及其中的证据关闭规则处理问题；交付前重新从来源检查遗漏，并读取[通用异常摘要](references/validation.md#读取通用异常摘要)。不以导出成功、细节增加或固定迭代次数作为完成条件。几何主体稳定后进入下述默认外观交付步骤。按[优先级](references/reconstruction.md#首版后的修正循环)推进：建筑缺失与漏缝、主体家具的缺失和明显偏差关闭之前，不制作装饰与小件细节。

完成报告说明改动对象、相关验证及其基线、剩余失败的位置和影响。只有运行过的验证可标为已实测；区分源码核实、推断和待验证。

### 默认外观交付步骤

几何稳定后依次完成 **appearance 取色与可靠性筛选 → 程序化 PBR 与米制 UV → 同视角照片／渲染复核 → 实际 GLB 导出检查 → 重开与查看器复核**。在 `STATE.md` 的外观阶段和材质覆盖表逐项记录证据、状态与当前版本；旧任务补齐这两张表。详细执行方法见 [默认外观流程](references/blender-materials.md#默认外观流程)。

最终及重开导出的 GLB 都运行 `restruct check-materials`，用 startup 的 `check_materials_prefix` 保留素材根绑定；读取 `materials.json` 并确认 `passed: true`。零图片、部分部件漏赋材质、缺 PBR 通道或 UV 失败不能算交付通过。玻璃／屏幕／均匀金属等无纹理材质逐 ID 写明例外理由，不为通过检查把全部材质排除。没有照片或取色不可靠时，记录证据限制与推断依据，不能自动跳过外观。仅用户明确要求的纯几何、碰撞或只读诊断范围可记“不适用”，并保留原任务依据。

外观阶段仍待做、阻塞或导出检查失败时，整屋任务不能报告完成；如需提前展示，标明几何预览或未完成外观。验证通过说明导出契约正确，材质是否符合照片仍须实际查看。

此技能保留决策方法，不复制项目生成器或硬编码特定场景参数。API 改动优先更新项目 README 与 `describe()`；新增经验应对应一个实际失败和已验证修正，放入最相关的参考文件，替换过时做法；避免累计互相冲突的规则。
